# 可访问性设计基线

> 性质：**设计期基线**，不是 WCAG 合规声明。最终合规需要在真实原型/代码上用键盘、读屏、缩放和辅助技术验证。
>
> 目标级别：默认按 WCAG 2.2 AA 设计；项目可以更严，但不能把本文当成法律或审计结论。

## 1. 适用范围

本文覆盖设计稿和可交互原型阶段能提前发现的问题：

- 视觉：对比度、字号、焦点环、目标尺寸、颜色之外的状态提示。
- 结构：标题层级、阅读顺序、控件名称、错误提示。
- 交互：键盘路径、焦点是否被遮挡、拖拽替代、超时和认证。
- 内容：链接/按钮文案、表单标签、错误恢复说明。

不覆盖：真实读屏器兼容性、浏览器/平台差异、后端权限和完整法律合规。

## 2. POUR 检查

### 2.1 可感知

- 正文对比度 ≥ 4.5:1；大号文本 ≥ 3:1；非文本控件/焦点 ≥ 3:1。
- 不用颜色作为唯一信息：错误、选中、禁用、必填同时给图标/文案/形状。
- 图片有 alt 意图；装饰图不抢读屏焦点；图标按钮有可读名称。
- 文本支持 200% 缩放不丢内容；不要用固定高度裁掉放大后的文字。
- 视频/音频有字幕或文字稿；动态内容提供暂停/停止。

### 2.2 可操作

- 所有功能可用键盘到达和操作；不设键盘陷阱。
- 焦点可见：项目基线 2px 焦点环，与相邻颜色对比 ≥ 3:1；焦点不能被粘性头/浮层完全遮挡。
- 目标尺寸：WCAG 2.2 AA 的最低要求是 24×24 CSS px；移动端按 44×44 执行。相邻小目标要有足够间距。
- 拖拽操作要有单点/键盘替代；不能只支持拖拽排序。
- 超时前提示并可延长；认证不依赖记忆/拼图等认知测试，允许粘贴密码/验证码。

### 2.3 可理解

- 表单控件有可见标签，不用 placeholder 代替标签。
- 错误说明“哪个字段、为什么错、怎么改”；错误汇总可定位到字段。
- 同一产品内帮助入口、术语和操作顺序一致。
- 不要求用户重复输入已提供的信息；必要时应可自动带出或选择。
- 链接/按钮文案能独立表达目的，避免一堆“了解更多”。

### 2.4 健壮

- 标题层级连续，不用字号/加粗假装标题。
- 控件有角色、名称、状态；自定义控件不能只画外观。
- 错误、加载、成功状态可被辅助技术感知；不要只弹一个视觉 toast。
- 设计标注中写清读屏名称、焦点顺序、错误关联和动态区域。

## 3. 设计标注表

每个关键屏幕交付时附一张表：

| 元素 | 角色 | 可读名称 | 状态 | 焦点顺序 | alt/说明 | 错误/动态 |
|---|---|---|---|---|---|---|
| 搜索按钮 | button | 搜索 | default/focus | 3 | 图标无需单独朗读 | 提交失败时读错误 |
| 头像 | image | 用户头像 | default | 不进入 | alt=用户名 | — |
| 关闭图标 | button | 关闭对话框 | focus | 1 | — | Esc 可关闭 |

规则：

- 图标按钮必须有名称；纯装饰图标标记为装饰。
- 焦点顺序按视觉阅读顺序写，不按图层顺序猜。
- 动态区域写明“何时播报、播报什么”，避免读屏器反复打断。

## 4. 哪些能在 Penpot 查，哪些必须到原型/代码

| 检查项 | Penpot/设计稿 | 原型/代码/辅助技术 |
|---|---|---|
| 对比度、字号、目标尺寸 | 可查 | 复核实际渲染 |
| 焦点环是否可见 | 可画 | 键盘实际走查 |
| 焦点是否被遮挡 | 难 | 必须 |
| 键盘顺序/陷阱 | 只能标注 | 必须 |
| 读屏名称/角色/状态 | 只能标注 | 必须 |
| 200% 缩放/重排 | 只能做压力稿 | 必须 |
| 减少动态效果 | 只能标注 | 必须 |
| 拖拽替代、认证、超时 | 只能设计 | 必须 |
| 错误播报/动态区域 | 只能标注 | 必须 |

不要把“设计稿里有焦点环”写成“键盘可访问已通过”。

## 5. 验收清单

- [ ] 文本对比度达标，禁用态也没有低到不可读
- [ ] 非文本控件和焦点环对比度 ≥ 3:1
- [ ] 状态不只靠颜色
- [ ] 图标按钮有可读名称，装饰图不进入读屏
- [ ] 表单有可见标签、字段级错误和错误汇总
- [ ] 键盘可完成主任务，焦点可见且不被遮挡
- [ ] 目标尺寸 ≥ 24×24；移动端 ≥ 44×44
- [ ] 拖拽有替代操作
- [ ] 200% 缩放不丢内容
- [ ] 减少动态效果有处理
- [ ] 认证不依赖记忆/认知测试
- [ ] 设计标注表已填写
- [ ] 明确声明“未做真实读屏/合规审计”

## 6. 常见失败

| 现象 | 问题 | 处理 |
|---|---|---|
| placeholder 当标签 | 输入后标签消失 | 加持久可见 label |
| 错误只用红色 | 色觉用户无法识别 | 图标 + 文案 + 字段提示 |
| 焦点环被 overflow 裁掉 | 键盘用户丢失位置 | 给焦点环留空间或提高层级 |
| 图标按钮无名称 | 读屏只读“按钮” | 加可读名称/aria-label |
| 24px 小按钮挤在一起 | 触控误点 | 增大到 44 或拉开间距 |
| 只支持拖拽排序 | 键盘/开关用户无法操作 | 提供上移/下移/选择位置 |
| 弹窗没有焦点管理 | 焦点跑到背景 | 打开聚焦、Esc 关闭、关闭后归还 |
| 设计稿通过就宣称合规 | 静态稿无法证明读屏/键盘 | 明确证据边界，补真实测试 |

## 7. 依据

- W3C, *Web Content Accessibility Guidelines (WCAG) 2.2*。
- W3C, *Accessibility Maturity Model*：可访问性需要流程、培训、工具和治理，不只是单次检查。
- NHS Digital Service Manual, *Design System*：一致、可访问的组件与 WCAG 2.2 更新实践。
- 现有 `docs/design/principles.md` 的对比度、触控目标、焦点和颜色基线。
