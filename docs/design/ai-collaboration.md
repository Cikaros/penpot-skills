# AI 协作规范

> 性质：**项目协作规范**。AI 是执行与生成工具，不是事实来源、业务决策者或验收人。
>
> 与 `principles.md` 第 2 节的分工：那里是十条提示原则；本文是输入、证据、评审和安全的完整契约。

## 1. 能做与不能做

适合交给 AI：

- 读取结构、批量重命名、生成重复布局；
- 按已有 token/组件做变体和新页面；
- 把设计结构转成代码骨架；
- 生成测试任务、边界文案、状态清单；
- 对产物做静态检查和差异汇总。

不能交给 AI 单独决定：

- 业务规则、权限、定价、合规；
- 用户研究和可用性结论；
- 品牌识别与法律风险；
- 真实项目文件的最终验收；
- 没有证据的“用户会喜欢/不会喜欢”。

## 2. 输入包

每次任务至少提供：

```text
目标：要改变什么，不是“做一个页面”
上下文：产品、用户、场景、现有流程
输入：文件/页面/board id、token、组件、参考图
约束：尺寸、断点、字体、颜色、禁止项
验收：可测量的条件（尺寸、状态、对比度、导出）
非目标：这次明确不做的事
证据边界：哪些是真实文件，哪些是合成/占位
```

规则：

- 指图片时说清“看哪一块、忽略哪一块”。
- 给规则而不是只给链接；链接可能失效，模型也可能不读。
- 没有真实数据时明确写“占位”，不要让它伪装成业务事实。
- 一次只改一个层级：结构、视觉、交互、代码不要混在一轮。

## 3. 提示契约

```text
角色：<有边界的角色，例如“懂设计系统与 WCAG 的资深产品设计师”>
任务：<一个可验收的改动>
输入：<文件/board/组件/token/图片>
约束：<必须遵守的规则>
输出：<格式：CSV/JSON/代码/画板清单>
验收：<如何判断成功>
停止条件：<缺数据/冲突/需要业务决策时停止并提问>
```

负向约束要具体：

- 不新增导航；
- 不改品牌标识；
- 不引入 token 外的颜色；
- 不假设未给出的业务规则；
- 不删除用户内容；
- 不把合成页结果写成真实文件结论。

## 4. 产物与证据

AI 产物分四类，验收方式不同：

| 产物 | 例子 | 验收 |
|---|---|---|
| 结构 | board 树、图层清单 | 读回 id/name/type/坐标 |
| 视觉 | 颜色、间距、字体 | token 映射 + 截图/导出 |
| 交互 | 状态、跳转、错误恢复 | 可点击原型/键盘走查 |
| 代码 | CSS/HTML/组件 | 构建、测试、token 审计 |

证据标签沿用 `docs/engineering/COMPASS.md`：

- `[实测-合成页]`：临时验收页；
- `[实测-真实文件]`：真实项目文件；
- `[源码]`：上游源码/官方文档；
- `[推断]`：基于相邻行为；
- `[待验证]`：未验证，不得当操作依据。

AI 生成的“看起来正确”不是证据。必须能指向文件、board id、导出字节、测试输出或人工走查记录。

## 5. 评审门

| 门 | 谁负责 | 看什么 | 不通过就 |
|---|---|---|---|
| 事实门 | 执行者 | API/版本/证据级别 | 补探针或降级为待验证 |
| 设计门 | 设计 owner | 层级、token、组件、状态 | 回退到规范/补 token |
| 代码门 | 工程 owner | 结构、可维护性、构建 | 不合并 |
| 可访问性门 | 设计 + 工程 | 对比度、键盘、焦点、名称 | 阻断或加防护 |
| 业务门 | 产品 owner | 规则、权限、文案 | 不做，等决策 |

AI 可以准备评审材料，但不能替代对应 owner 签字。

## 6. 隐私与安全

- 不把密钥、token、客户名单、未公开财务数据粘贴到外部模型。
- 需要真实截图时先脱敏；保留最小必要信息。
- 不把生产环境凭证写进提示、代码或仓库。
- 生成代码先审依赖和网络请求；不运行来源不明的脚本。
- 对外发布前确认许可证、字体、图片和商标权限。

## 7. 失败模式

| 现象 | 原因 | 处理 |
|---|---|---|
| 一次生成整页，结构全错 | 任务太大 | 拆成结构 → 区块 → 组件 |
| 颜色/间距全是魔数 | 没给 token 或没做后处理 | 提供 token 表；生成后审计 |
| 反复“优化”但不知道对不对 | 没有验收条件 | 先写成功/失败信号 |
| 把合成页当真实文件 | 证据边界没写 | 标注文件/页面来源 |
| 生成不可维护的组件 | 没有 API/状态约束 | 按 `design-system.md` 定义 API |
| 文案像营销稿 | 没给语气和长度 | 给示例、禁用词、字数上限 |
| 交互只做 happy path | 没给状态矩阵 | 按 `states.md` 补空/错/离线/权限 |

## 8. 验收清单

- [ ] 目标和验收条件可测量
- [ ] 输入含文件/board/组件/token 的具体位置
- [ ] 明确非目标和负向约束
- [ ] 明确证据边界，没有把合成页写成真实文件
- [ ] 产物有 id/路径/测试输出可追溯
- [ ] 经过事实、设计、代码、可访问性门
- [ ] 业务决策由人确认
- [ ] 敏感数据已脱敏，凭证未进入提示或仓库
