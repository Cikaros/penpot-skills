# 设计简报模板

> 用途：把"帮我做好看点"翻译成模型可执行、你可验收的输入。

## 1. 模板

```text
Context: 产品=?? 用户=?? 文件/页面=?? 目标画板=??
Goal: 本次只解决的一个问题
Inputs: 现有 token/组件、参考图（标明看哪一部分）
Constraints: 只用现有组件；WCAG AA；不自创颜色；不改导航
Quality: 可测量的验收条件（尺寸、层级数、对比度、导出图）
Non-goals: 本次明确不做的事
```

如果这次要验证设计假设，先按 [`prototyping.md`](prototyping.md) 补“问题 / 假设 / 保真度 / 证据 / 决策”，再开始画；测试执行按 [`usability-test.md`](usability-test.md)。

## 2. 示例 A：修复缺图与错位

```text
Context: 移动端 App，文件 app-mobile-v2，页面 03-Screens，画板 profile-Profile-Default（390×844）
Goal: 恢复"我的"页 18 个图片位，并修正 102 个子元素的越界
Inputs: 现有图标来自 cmp-base-Icon；头像为圆形裁切
Constraints: 不改布局结构；图片必须为真实 PNG；不新增颜色
Quality: 18 个 fillImage 均存在且宽高 > 0；所有子元素在画板内；导出 PNG 目视无空白
Non-goals: 不重排信息架构，不改文案
```

## 3. 示例 B：新建首页

```text
Context: 同一文件，新建页面 03-Screens，画板 home-Home-Default（390×844）
Goal: 按 11 个区块还原首页：顶栏、搜索、快捷标签、AI 助手宫格、公告条、双卡、ETC banner、路况横滑、丹霞 banner、公告列表、底栏
Inputs: 复用 cmp-base-*；间距按 space-*；颜色按 color-*
Constraints: 只用已有 token；横滑区宽度超出画板时用 board clipContent，不缩小子元素
Quality: 11 个区块齐全；区块间距 24/32；导出图与参考图结构一致
Non-goals: 不做交互原型，不接真实数据
```

## 4. 负向清单（直接抄）

- 不要新增导航模式或入口。
- 不要修改品牌色与 logo。
- 不要发明断点、间距、字号。
- 不要假设业务规则（价格、权限、流程）。
- 不要为了"更现代"替换整套组件。
- 不要在未确认的情况下删除原有内容。

## 5. 验收条件的写法

可测量，不写形容词：

| 不要写 | 改成 |
|---|---|
| 看起来更清爽 | 同屏边框数量从 12 降到 4；字号层级从 5 档降到 3 档 |
| 间距统一 | 所有区块间距为 24 或 32；无 13/18/22 等非标值 |
| 图片正常 | 18 个 fillImage 存在；导出 PNG 无空白区域 |
| 适配移动端 | 390×844 下无横向溢出；触控目标 ≥ 44×44 |

## 6. 迭代节奏

1. **分析**：只读结构，输出问题清单（不改）。
2. **提案**：给出 2–3 个改法与取舍。
3. **落地**：按批准的方案分片执行。
4. **验收**：导出图 + 几何检查 + 简报逐条对照。

每一轮只推进一个阶段；不要在第一轮就要求全部完成。

## 7. 反例提示词

- "把这个页面做得高级一点"——没有目标、没有约束、无法验收。
- "参考这个链接重做"——模型无法访问时的静默降级会产出臆造内容。
- "全部改成 16 号字"——破坏层级，且未说明哪些是标题。
