# 状态覆盖基线

> 性质：**项目规范基线**。组件七态解决“控件怎么变”，本文解决“屏幕在数据和服务异常时是否还成立”。

## 1. 组件状态不等于屏幕状态

`components.md` 的 default/hover/pressed/focus/disabled/loading/error 是**控件级**状态。真实屏幕还需要：

- 数据为空；
- 首次加载和分页加载；
- 部分数据/过期数据；
- 网络离线；
- 无权限；
- 长文本/超长列表；
- 表单校验和提交结果。

只交默认态，等于把异常处理留给开发临场发挥。

## 2. 状态矩阵

| 范围 | 状态 | 何时必须有 | 最低要求 |
|---|---|---|---|
| 屏幕 | default | 所有屏幕 | 正常数据下的完整布局 |
| 屏幕 | loading | 首次加载/切换筛选 | 骨架屏保持尺寸，避免布局跳动 |
| 屏幕 | empty | 列表、搜索、消息、收藏 | 说明为什么空 + 下一步动作 |
| 屏幕 | error | 请求失败、保存失败、解析失败 | 说明影响 + 重试/返回 + 保留输入 |
| 屏幕 | partial/stale | 分页、缓存、弱网 | 标明数据范围和更新时间，不静默混用 |
| 屏幕 | offline | 移动端、弱网、离线优先 | 只读/排队/禁用要有解释 |
| 屏幕 | permission | 角色、套餐、登录态限制 | 隐藏或禁用要一致；说明申请路径 |
| 屏幕 | long-text | CJK/英文长文案、长用户名 | 不重叠、不截断关键信息、可读全文 |
| 表单 | validation | 输入校验 | 字段级错误 + 汇总 + 焦点定位 |
| 表单 | submitting | 提交中 | 防重复提交，保留已填内容 |
| 表单 | success | 提交成功 | 明确下一步，不只弹 toast |
| 组件 | hover/focus/pressed/disabled | 交互控件 | 五态齐全，焦点可见 |

### 2.1 最低交付集合

- 普通内容屏：default、loading、empty、error。
- 列表/搜索：再加 partial/stale、long-text。
- 表单：再加 validation、submitting、success。
- 权限相关：再加 permission。
- 离线优先：再加 offline。

## 3. 每个状态的交付规则

### 3.1 Loading

- 用骨架屏或占位块保持最终尺寸；不要先显示 0 高度再撑开。
- 超过 1 秒的加载要有进度或阶段说明；不要只放一个无标签 spinner。
- 分页加载不能清空已有内容。

### 3.2 Empty

- 说明“为什么空”，而不是只放插画。
- 给出一个主要下一步动作；没有权限时不要伪装成空数据。
- 搜索无结果要保留搜索词和清除入口。

### 3.3 Error

- 写清“发生了什么、影响什么、怎么恢复”。
- 提供重试或返回；可恢复错误不要直接丢弃用户输入。
- 错误不能只用红色；同时给图标/文案/字段提示。

### 3.4 Partial / Stale

- 标明数据范围、时间或来源；不要把缓存数据伪装成实时数据。
- 局部失败时保留可用区域，不要整屏报错。
- 需要时提供刷新入口和最后更新时间。

### 3.5 Offline

- 明确哪些操作可继续、哪些进入队列、哪些不可用。
- 禁用操作要说明原因和恢复条件，不要只变灰。
- 重新联网后给出同步结果，包括失败项。

### 3.6 Permission

- 同一产品内统一“隐藏”还是“禁用”的策略。
- 禁用时说明缺少什么权限、如何申请；不要用空白页代替。
- 不要把权限错误写成“网络错误”。

### 3.7 Long text

- 用 2×/3× 文案、长用户名、长地名做压力测试。
- 关键信息不能被省略号吞掉；需要时提供展开或详情。
- 中文和英文都要检查换行、行高和按钮内边距。

## 4. 命名与画板

沿用 `conventions.md` 的 board 命名，把状态放在最后：

```text
home-Home-Default
home-Home-Loading
home-Home-Empty
home-Home-Error
home-Home-Partial
vehicle-Add-Validation
vehicle-Add-Submitting
```

规则：

- 一屏一 board；状态是 board 后缀，不用隐藏图层假装状态。
- 同一屏幕的状态 board 连续排列，便于导出和对比。
- 需要对比时保持相同宽度和内容区，避免状态间布局跳变。
- 不使用 `/` 作为分隔符；Penpot 会归一化成 `" / "`。

## 5. 验收清单

- [ ] 每个屏幕至少有 default、loading、empty、error
- [ ] 表单有 validation、submitting、success
- [ ] 列表/搜索有 partial 或 stale、long-text
- [ ] loading 不改变最终布局尺寸
- [ ] empty 有原因和下一步动作
- [ ] error 有影响说明和恢复路径
- [ ] 状态切换不丢失用户输入
- [ ] 所有状态都有可见焦点和键盘路径
- [ ] 状态不只靠颜色区分
- [ ] 状态命名与 board 命名一致

## 6. 常见失败

| 现象 | 原因 | 处理 |
|---|---|---|
| 上线后空白页 | 只设计了 default | 补 empty/loading/error |
| 加载时页面跳动 | spinner 不占位 | 用同尺寸骨架屏 |
| 用户重复提交 | 没有 submitting 态 | 禁用按钮 + 保留输入 + 明确进度 |
| 局部失败整屏崩 | 没有 partial 态 | 保留可用区域，局部提示 |
| 无权限被当成空数据 | 状态语义混淆 | 单独做 permission 态 |
| 长文案重叠 | 只用最短文案验收 | 2×/3× 文案压力测试 |
| 状态只靠颜色 | 可访问性不足 | 图标/文案/边框/形状共同表达 |

## 7. Penpot 落地提示

- 用独立 board 表达状态，命名后缀统一；不要依赖隐藏图层。
- 改尺寸/插入子元素后 `await penpot.waitForLayoutUpdate()`，再读坐标。
- 越界检查按直接父容器逐层做，不能只比顶层 board。
- 只有 `execute_code` 时，导出字节校验只能证明“有图”，不能声称目视通过。

## 8. 依据

- Nielsen, *10 Usability Heuristics*：系统状态可见、错误预防、错误恢复。
- WCAG 2.2：错误识别、标签、一致帮助、状态不只用颜色。
- 现有 `docs/design/components.md` 的组件七态，以及 `docs/penpot-mcp/pitfalls.md` 的布局/越界实测。
